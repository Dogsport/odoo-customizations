Shopify instance archived by mistake – webhooks & schedulers restored (23.10.2026)

Status 23.10.2026, 17:40: solved. Shopify ↔ Odoo sync running normally again. One minor item (product-delete webhook) handed to Emipro.

Odoo 19 Production (iq-dogsport.odoo.com) · Emipro Shopify connector · instance IQ Dogsport Shopify (id 1). Credentials, tokens and customer data are intentionally not stored here. The commands below read the token from the database at run time and never print it.

All times are German time (CEST) unless marked UTC. Odoo.sh logs and the database use UTC (= CEST − 2 h).

1. Summary

  • While preparing staging for the DHL/GLS test, the Shopify instance was archived by mistake in Production (15:29:05) and reactivated 16 seconds later.
  • Archiving deleted the instance's webhook records in Odoo (and 2 of the 6 webhooks in Shopify), deleted the queues and switched off 2 schedulers. Reactivating did not restore webhooks or schedulers.
  • Effect: from 15:29 to 17:18 no Shopify orders reached Odoo automatically; stock and tracking were not sent to Shopify.
  • Fix: schedulers re-enabled, webhooks re-created one by one from the instance's Webhooks tab (old Shopify subscriptions removed first where they still existed), missed orders imported manually. Verified end to end.

Root cause: Odoo lost its webhook records, so it ignored what Shopify still sent. Re-enabling failed because Shopify still had subscriptions for the same topic and address ("already been taken"). There never was an orders/create webhook — new orders arrive through orders/updated.

5. Fix

5.1 Schedulers

Settings → Technical → Automation → Scheduled Actions → open "IQ Dogsport Shopify : Shopify Auto Export Stock" (105) and "IQ Dogsport Shopify : Shopify Auto Update Order Shipping Status" (101) → tick Active → save. Interval unchanged (30 min). Not the generic ones without prefix (48, 53).

5.2 Webhooks — one at a time

Shopify → Configuration → Instances → IQ Dogsport Shopify → Webhooks tab → Add a line. Do not use the Settings checkboxes (they fail and may create topics that did not exist before).

  1. Customers (no conflict, nothing to delete): Add a line → When Customer is Created → Name Customer Create → Save & Close. Same for When Customer is Updated.
  2. Orders / products (old subscription still in Shopify): prepare the line first (action + name, don't save) → run the delete command for exactly that one subscription ID → check "userErrors":[] → immediately Save & Close.

  3. After each step: run the read-only list command and check that exactly one subscription changed.

When Product is Deleted is not selectable in the form ("No results"). The old subscription 2227223789832 was not deleted and is left for Emipro.

5.3 Missed orders

Shopify → Operations → Import Orders (from 23.10.2026 15:00). Orders already in Odoo are skipped. #IQD-99051 imported manually; #IQD-99052 came in through the restored webhook.

8. Rules for next time

  • Never archive the Shopify instance — not in Production, not in staging. To point staging at the test store use Reset Credentials.
  • Before any change, check the browser address bar and the red "Database neutralized" banner. No banner = Production.
  • A new Odoo.sh staging build is a copy of Production, including Shopify credentials. Treat it as live until the credentials are changed.
  • Webhook health at a glance: new order queues created by Public user = webhooks work. Only manual ones = webhooks broken.
  • Investigate with read-only commands first (default_transaction_read_only=on), change one thing at a time, verify after each step.

9. All commands used (Odoo.sh → Production → SHELL)

read-only commands only read. CHANGES SHOPIFY commands change Shopify and were run once per subscription, each immediately followed by Add a line in Odoo.

9.1 Last run of each Shopify scheduler (logs) read-only

zgrep -h "ir_cron: Job '" ~/logs/odoo.log* | grep -i shopify | grep "starting" | grep -oE "^[0-9-]+ [0-9:]+|Job '[^']+' \([0-9]+\)" | paste - - | awk -F'\t' '{ if ($1 > last[$2]) last[$2]=$1 } END { for (k in last) print last[k] " UTC   " k }' | sort

9.2 Scheduler state in the database read-only

PGOPTIONS='-c default_transaction_read_only=on' psql -c "SELECT c.id, c.cron_name, c.active, c.interval_number, c.interval_type, c.lastcall AS last_run_utc, c.write_date AS changed_utc, u.login AS changed_by FROM ir_cron c LEFT JOIN res_users u ON u.id = c.write_uid WHERE c.cron_name ILIKE '%shopify%' ORDER BY c.active, c.write_date DESC;"

9.9 List webhook subscriptions in Shopify read-only

TOKEN=$(PGOPTIONS='-c default_transaction_read_only=on' psql -At -c "SELECT shopify_password FROM shopify_instance_ept WHERE id = 1;") && curl -s -X POST "https://iqdogsport.myshopify.com/admin/api/2026-04/graphql.json" -H "X-Shopify-Access-Token: $TOKEN" -H "Content-Type: application/json" -d '{"query":"{ webhookSubscriptions(first: 100) { edges { node { id topic createdAt endpoint { __typename ... on WebhookHttpEndpoint { callbackUrl } } } } } }"}' | python3 -c "import sys,json; d=json.load(sys.stdin); r=[e['node'] for e in d.get('data',{}).get('webhookSubscriptions',{}).get('edges',[])]; [print(n['topic'],'|',n['endpoint'].get('callbackUrl'),'|',n['createdAt'],'|',n['id']) for n in r]; print(len(r),'webhooks found') if r else print(d)"; unset TOKEN

Used for 2227223822600 (orders/updated), 2227223757064 (products/update), 2227223724296 (products/create). Example:

TOKEN=$(PGOPTIONS='-c default_transaction_read_only=on' psql -At -c "SELECT shopify_password FROM shopify_instance_ept WHERE id = 1;") && curl -s -X POST "https://iqdogsport.myshopify.com/admin/api/2026-04/graphql.json" -H "X-Shopify-Access-Token: $TOKEN" -H "Content-Type: application/json" -d '{"query":"mutation { webhookSubscriptionDelete(id: \"gid://shopify/WebhookSubscription/2227223822600\") { deletedWebhookSubscriptionId userErrors { field message } } }"}'; echo; unset TOKEN
