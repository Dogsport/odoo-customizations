Unpaid Shopify deliveries jump from Waiting to Ready – fix of automation rule 21

Date: 30.10.2026 · Author: Hamza Mohsin · System: Odoo 19 (Inventory) Status: Staging ✅ tested 30.10.2026 · Production ⏳ _ (date) Asana: (add task link)_

Problem

Unpaid Shopify delivery orders (tag "Zahlung ausstehend") sometimes changed from Waiting to Ready by themselves. The chatter showed the change under the name of the user who was working at that moment (e.g. Elena), although she never opened that order.

Example (production): WH1/OUT/07401 (#IQD-99211) – 29.10.2026 12:19 "Wartend → Bereit" (Elena Kistritz). At exactly 12:19 Elena validated return WH1/RET/00564 (same product IQD-EKL-MJD3.BK.XL back into WH1/Stock). Same pattern: WH1/OUT/06641 reserved at 28.10.2026 11:48 when WH1/RET/00545 was validated.

Root cause

  1. Standard Odoo: when stock comes in (return, receipt), Odoo automatically reserves it for waiting deliveries → Ready.
  2. Automation rule 21 ("Change status of Transfer (For Business Partners EU and Abroad)", server action 1602) pushed Ready deliveries back to Waiting – but only once: it set the field x_studio_auto_unreserved = True and both the "Apply on" domain and the code skipped every delivery that already had this flag.
  3. So the first reservation was undone, every later one (return, receipt, scheduler) was not. The flag could not tell a manual release from an automatic reservation.
  4. The rule also only covered fiscal positions 5/6 (Business partner EU / abroad) and gateway 21 (Bank Deposit), not all unpaid Shopify orders.

The defect & repair automations (IQ – …) were checked and are not involved (they never change transfer status).

Investigation (staging shell, read-only)

  • grep -rn "Zahlung ausstehend" ~/src/user → nothing (tag is set by hand).
  • Automation rules on Transfer: 21 (this rule), 27 "Block delivery if not paid" (blocks Validate only), 42 "Waiting-Lieferung: nur berechtigte Benutzer" (blocks Waiting→Done for users without group).
  • Shopify connector shopify_ept/models/sale_order.py:773 only skips payment registration for pending orders – does not touch deliveries.
  • x_studio_auto_unreserved = true on WH1/OUT/06641 and WH1/OUT/06820 confirmed the one-time flag.

New logic (when a delivery becomes Ready)

Order Result
Created by staff in Odoo (no Shopify instance) stays Ready – never blocked
Shopify, invoice paid / in payment / reversed stays Ready
Shopify, unpaid, allowed user clicks Check Availability on it stays Ready + chatter "Unbezahlte Shopify-Lieferung manuell freigegeben durch …"
Shopify, unpaid, anything else (return/receipt validated, scheduler, other user) back to Waiting + chatter "Shopify-Bestellung nicht bezahlt – automatisch zurück auf Wartend."

Allowed users (same as rule 27): Anastasiia Derkach, Florian Knabl, Elena Kistritz, Hamza Mohsin. "Stock came in" is detected by Odoo's context key button_validate_picking_ids (present while another transfer is validated).

Changes in rule 21

Setting Before After
Before Update state ≠ Ready unchanged
Apply on Delivery, Ready, auto unreserved not set, fiscal position 5/6 or gateway Bank Deposit [("picking_type_code","=","outgoing"), ("state","=","assigned")]
When updating Type of Operation, Sales Order, Status, auto unreserved Type of Operation, Status
Code see code/automation_rule_21_BEFORE.py see code/automation_rule_21_AFTER.py
Name (optional) Change status of Transfer (For Business Partners EU and Abroad) Unbezahlte Shopify-Lieferung zurück auf Wartend

Field x_studio_auto_unreserved is no longer used (not deleted). No new fields.

Production rollout

  1. Backup: copy old code (= BEFORE file) + screenshot of Apply on / When updating.
  2. Apply on, When updating, Code as above. Save.
  3. Smoke test: unpaid Waiting Shopify order → Check Availability (as allowed user) → Ready + release note → Unreserve.
  4. Do not run receipt/return tests in production.

Rollback: paste BEFORE code back, re-add auto unreserved is not set and the fiscal position / Bank Deposit block to Apply on.

Known limits / follow-ups

  • An inventory adjustment (Apply) by an allowed user has no "validate" marker → would count as a manual release (rare).
  • Unpaid orders can still hold part of the stock while Waiting (partial reservation) – cannot ship, but blocks those items for paid orders.
  • "In Payment" counts as paid (correct for Shopify Payments; for Bank Deposit only once a payment is registered). Rule 27 uses the same check.
  • Tag "Zahlung ausstehend" is manual and can be outdated (e.g. 06820 is card-paid).
  • Related, separate topics: Zoll orders are not held by any rule; Shipping Policy "When all products are ready" for partly available orders.

Code – before

# Automation rule 21 "Change status of Transfer (For Business Partners EU and Abroad)"
# Server action 1602 (Execute Code) - ORIGINAL code before 2026-10-30
# Model: Transfer | Trigger: On create and edit
# Before Update: [("state", "!=", "assigned")]
# Apply on: [ "&","&","&", ("picking_type_code","=","outgoing"), ("state","=","assigned"),
#             ("x_studio_auto_unreserved","=",False),
#             "|", ("sale_id.fiscal_position_id","in",[6,5]), ("sale_id.shopify_payment_gateway_id","in",[21]) ]
# When updating: sale_id, state, picking_type_code, x_studio_auto_unreserved
# Fiscal positions 5/6 = Business partner EU (with VAT ID) / Business partner abroad (non-EU); gateway 21 = Bank Deposit

for picking in records:

    # Only outgoing deliveries
    if picking.picking_type_code != 'outgoing':
        continue

    # Only when in Ready state
    if picking.state != 'assigned':
        continue

    # Prevent re-running
    if picking.x_studio_auto_unreserved:
        continue

    # STEP 1: Set done/reserved qty = 0 (unreserve)
    for move in picking.move_ids:
        for line in move.move_line_ids:
            line.write({
                'quantity': 0
            })

    # STEP 2: Remove reservation layer completely
    if picking.move_line_ids:
        picking.move_line_ids.unlink()

    # STEP 3: Force moves back to WAITING
    for move in picking.move_ids:
        if move.state not in ('done', 'cancel'):
            move.write({
                'state': 'confirmed'
            })

    # STEP 4: Force picking state to WAITING
    picking.write({
        'state': 'confirmed',
        'x_studio_auto_unreserved': True
    })

Code – after

# Automation rule 21 (suggested new name: "Unbezahlte Shopify-Lieferung zurück auf Wartend")
# Server action 1602 (Execute Code) - NEW code from 2026-10-30
# Model: Transfer | Trigger: On create and edit
# Before Update: [("state", "!=", "assigned")]          (unchanged)
# Apply on:      [("picking_type_code", "=", "outgoing"), ("state", "=", "assigned")]
# When updating: picking_type_code, state

allowed_logins = [
    'anastasiia.derkach@iq-dogsport.de',
    'florian.knabl@iq-dogsport.de',
    'elena.kistritz@iq-dogsport.de',
    'hamza.mohsin@iq-dogsport.de',
]

for picking in records:

    # Only outgoing deliveries in Ready state
    if picking.picking_type_code != 'outgoing' or picking.state != 'assigned':
        continue

    so = picking.sale_id

    # Rule 1: staff-created order (not Shopify) -> never blocked
    if not so or not so.shopify_instance_id:
        continue

    # Rule 2: Shopify order already paid -> may stay Ready
    posted = so.invoice_ids.filtered(lambda m: m.state == 'posted')
    if posted.filtered(lambda m: m.payment_state in ('paid', 'in_payment', 'reversed')):
        continue

    # Rule 3: allowed user clicked Check Availability on THIS order
    # (not stock coming in from validating a return/receipt)
    side_effect = bool(env.context.get('button_validate_picking_ids'))
    if env.user.login in allowed_logins and not side_effect:
        picking.message_post(body='Unbezahlte Shopify-Lieferung manuell freigegeben durch %s.' % env.user.name)
        continue

    # Otherwise: unpaid Shopify order -> back to Waiting
    for move in picking.move_ids:
        for line in move.move_line_ids:
            line.write({'quantity': 0})
    if picking.move_line_ids:
        picking.move_line_ids.unlink()
    for move in picking.move_ids:
        if move.state not in ('done', 'cancel'):
            move.write({'state': 'confirmed'})
    picking.write({'state': 'confirmed'})
    picking.message_post(body='Shopify-Bestellung nicht bezahlt – automatisch zurück auf Wartend.')
