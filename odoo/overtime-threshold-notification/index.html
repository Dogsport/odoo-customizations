Overtime threshold notification: weekly check + month-end summary

Live — weekly check (Mondays) Open — month-end summary first real run 31.10.2026
22.10.2026 · updated 26.10.2026 · Production (iq-dogsport.odoo.com) · hr.employee · Scheduled Action
Prepared for: Dr. Florian Knabl

Change 26.10.2026: weekly check on Mondays, always notify

  • The weekly check now runs only on Mondays and looks at the previous week (Monday–Sunday) instead of a rolling 7-day window that moved every day.
  • A new to-do is created every week an employee is over the threshold, even if the previous week's to-do is still open. Before, an open to-do blocked any new one.
  • The week is now part of the to-do title, e.g. "Overtime threshold exceeded (19.10.2026 - 25.10.2026)", so several open weeks can be told apart in My Activities.
  • Each to-do shows only that week's overtime hours — weeks are never added together.
  • Duplicate protection only applies to the same week (e.g. if the action is run twice on the same Monday).
  • The scheduled action still runs daily so the month-end summary keeps working; the weekly block simply skips non-Monday days.
  • Month-end summary block unchanged. No new fields, views or groups.

What the manager does with the to-do

  1. Open the to-do and go to the employee — the note shows the week's overtime and the threshold.
  2. Check the employee's attendances for that week (which days caused it, any forgotten check-out).
  3. Correct wrong attendance entries if needed.
  4. Decide on real overtime (accept, compensate with time off, talk to the employee if it repeats).
  5. Mark the to-do Done, optionally with a short note on the decision.

What was achieved (22.10.2026)

  • Replaced the existing "Daily Overtime Threshold Check" cron's logic: it used to compare each employee's lifetime overtime balance (total_overtime) to a threshold, which never resets — once crossed, an employee stayed flagged indefinitely even after the underlying overtime week was long over.
  • New logic sums each employee's actual clocked overtime (already net of the ArbZG break deduction) and compares that to a threshold scaled to that employee's own weekly contracted hours (10% currently, configurable in Settings → Attendances → Extra Hours — no code change needed to adjust the percentage). Since 26.10.2026 the window is the previous Monday–Sunday week (see above).
  • Notification goes to the employee's manager plus all Administrators (currently Florian or the relevant manager, Hamza, Patricia) as a to-do activity, with the exact numbers written into the note.
  • Added a second, independent block to the same cron: on the last calendar day of each month, it totals each employee's full month-to-date overtime and posts a separate "Monthly overtime summary" to-do to the same recipients — satisfies the follow-up ask for monthly visibility, not just weekly threshold breaches.
  • Cleaned up 15 stale "Overtime threshold exceeded" to-dos that the old (incorrect) lifetime-balance logic had created for 6 employees.
  • Live-tested the weekly check after the rewrite: correctly flagged only the one employee genuinely over their weekly threshold, and correctly cleared employees who still carry a high lifetime balance but had a normal recent week.
  • No new fields, views, or groups — this was a code-only change inside an automation that already existed.

What is left

  • The 3 open to-dos from the old logic (Manuela May, Anastasiia Derkach, Markus Liebetanz) can be marked Done or cancelled.

  • Threshold percentage is still a single company-wide setting (10%) — no per-employee override exists yet if that's ever needed.
  • No email/digest option — notifications are Odoo activity to-dos only, not emails, by design so far.
  • Florian has not yet confirmed the recipient list (manager + both Administrators) is the right long-term group, or whether it should narrow over time.

Automation rule

SettingValue
TypeScheduled Action (ir.cron)
NameDaily Overtime Threshold Check
ModelEmployee (hr.employee)
RunsEvery 1 day, 9:59 AM — weekly block only acts on Mondays, monthly block only on the last day of the month
Weekly windowPrevious Monday 00:00 – Sunday 23:59
RecipientsEmployee's manager (parent_id.user_id) + Administrators (base.group_system)
DedupWeekly: skips only if a to-do for the same week already exists for that employee/user pair. Monthly: skips if a summary with today's date already exists.
company = env.company
today = datetime.date.today()

# --- Weekly overtime threshold check (runs only on Mondays, checks previous Mon-Sun) ---
threshold_percent = company.x_overtime_threshold_percent or 0.0
if threshold_percent > 0 and today.weekday() == 0:
    Employee = env['hr.employee'].sudo()
    Attendance = env['hr.attendance'].sudo()
    Activity = env['mail.activity'].sudo()
    activity_type = env.ref('mail.mail_activity_data_todo')
    hr_model_id = env['ir.model']._get_id('hr.employee')
    admin_users = env.ref('base.group_system').sudo().user_ids
    week_start = today - datetime.timedelta(days=7)   # last Monday
    week_end = today - datetime.timedelta(days=1)     # yesterday (Sunday)
    week_start_dt = datetime.datetime.combine(week_start, datetime.time.min)
    week_end_dt = datetime.datetime.combine(week_end, datetime.time.max)
    week_label = "%s - %s" % (week_start.strftime('%d.%m.%Y'), week_end.strftime('%d.%m.%Y'))
    summary = "Overtime threshold exceeded (%s)" % week_label
    employees = Employee.search([('company_id', '=', company.id)])
    for emp in employees:
        calendar = emp.resource_calendar_id
        if not calendar or not calendar.hours_per_week:
            continue
        threshold_hours = calendar.hours_per_week * (threshold_percent / 100.0)
        attendances = Attendance.search([
            ('employee_id', '=', emp.id),
            ('check_in', '>=', week_start_dt),
            ('check_in', '<=', week_end_dt),
        ])
        week_overtime = sum(attendances.mapped('validated_overtime_hours'))
        if week_overtime <= threshold_hours:
            continue
        recipients = env['res.users']
        if emp.parent_id and emp.parent_id.user_id:
            recipients |= emp.parent_id.user_id
        recipients |= admin_users
        note = (
            "<p><strong>%s</strong> worked %.2f overtime hours in the week %s, "
            "above the %.0f%% threshold of their %.1fh/week contract "
            "(threshold: %.2f hours).</p>"
            % (emp.name, week_overtime, week_label, threshold_percent,
               calendar.hours_per_week, threshold_hours)
        )
        for user in recipients:
            # Only prevents a duplicate for the SAME week (e.g. if run twice on the same Monday).
            # Open to-dos from earlier weeks do NOT block a new one.
            existing = Activity.search([
                ('res_model', '=', 'hr.employee'),
                ('res_id', '=', emp.id),
                ('activity_type_id', '=', activity_type.id),
                ('user_id', '=', user.id),
                ('summary', '=', summary),
            ], limit=1)
            if existing:
                continue
            Activity.create({
                'res_model': 'hr.employee',
                'res_model_id': hr_model_id,
                'res_id': emp.id,
                'activity_type_id': activity_type.id,
                'user_id': user.id,
                'summary': summary,
                'note': note,
                'date_deadline': today,
            })

# --- Monthly overtime summary (fires only on the last calendar day of the month) ---
if today.month == 12:
    next_month_start = today.replace(year=today.year + 1, month=1, day=1)
else:
    next_month_start = today.replace(month=today.month + 1, day=1)
last_day_of_month = next_month_start - datetime.timedelta(days=1)
if today == last_day_of_month:
    Employee = env['hr.employee'].sudo()
    Attendance = env['hr.attendance'].sudo()
    Activity = env['mail.activity'].sudo()
    activity_type = env.ref('mail.mail_activity_data_todo')
    hr_model_id = env['ir.model']._get_id('hr.employee')
    admin_users = env.ref('base.group_system').sudo().user_ids
    month_start = today.replace(day=1)
    month_start_dt = datetime.datetime.combine(month_start, datetime.time.min)
    month_end_dt = datetime.datetime.combine(today, datetime.time.max)
    employees = Employee.search([('company_id', '=', company.id)])
    for emp in employees:
        calendar = emp.resource_calendar_id
        if not calendar or not calendar.hours_per_week:
            continue
        attendances = Attendance.search([
            ('employee_id', '=', emp.id),
            ('check_in', '>=', month_start_dt),
            ('check_in', '<=', month_end_dt),
        ])
        month_overtime = sum(attendances.mapped('validated_overtime_hours'))
        if month_overtime <= 0:
            continue
        recipients = env['res.users']
        if emp.parent_id and emp.parent_id.user_id:
            recipients |= emp.parent_id.user_id
        recipients |= admin_users
        note = (
            "<p><strong>%s</strong> worked %.2f extra hours in total during %s "
            "(%s to %s).</p>"
            % (emp.name, month_overtime, today.strftime('%B %Y'), month_start, today)
        )
        for user in recipients:
            existing = Activity.search([
                ('res_model', '=', 'hr.employee'),
                ('res_id', '=', emp.id),
                ('activity_type_id', '=', activity_type.id),
                ('user_id', '=', user.id),
                ('summary', '=', 'Monthly overtime summary'),
                ('date_deadline', '=', today),
            ], limit=1)
            if existing:
                continue
            Activity.create({
                'res_model': 'hr.employee',
                'res_model_id': hr_model_id,
                'res_id': emp.id,
                'activity_type_id': activity_type.id,
                'user_id': user.id,
                'summary': 'Monthly overtime summary',
                'note': note,
                'date_deadline': today,
            })

Related
