DHL return label + reclamation form by email – one button (29.10.2026)

PDF version · Code files

Status 29.10.2026 – live in production. One button on a return creates the DHL return label (if needed) and opens a prepared email to the customer with the label and the reclamation form, in German or English. Returns from a ticket are emailed from the ticket, so replies land in the ticket. Owner: Hamza. Users: Elena / Customer Care.

1. What it does

Return created (from ticket, sales order or delivery) └─ Automation: German customer + carrier empty → Carrier = DHL Parcel DE, Receiver = deu Click "Retourenlabel senden" ├─ label already on the return? → reuse it (no second DHL label) ├─ no label yet → create it via DHL (= "Print Return Label") │ DHL error → error shown, no email window ├─ customer language de_* → template (DE) + Retourenschein DE │ otherwise → template (EN) + Retourenschein EN └─ email window opens (editable) with label + Retourenschein return belongs to a ticket → email posted in the TICKET (replies come back there) no ticket → email posted in the RETURN Click "Senden" → email to the customer (from mail@iq-dogsport.de) Label exists → button changes to "Retourenlabel erneut senden" (asks for confirmation, reuses label)

2. How staff use it

  1. Create the return as usual (ticket → Return, sales order or delivery → Return).
  2. Check: Carrier DHL Parcel DE, DHL Return Receiver deu (set automatically for customers in Germany).
  3. Click Retourenlabel senden. Wait a few seconds (DHL).
  4. Check the email (text, recipient, 2 PDFs), change the text if needed, click Senden.
  5. If the window was closed without sending: click Retourenlabel erneut senden – the same label is used.
Closing the email window does not delete the label – it was already created at DHL. Unused return labels are not charged (DHL bills only transported returns – confirm against the IQ Dogsport contract).

4. Automation: DHL carrier for Germany

Odoo does not copy the carrier from the delivery to the return, and the sales-order carrier rules do not apply to returns. Without a carrier the DHL buttons are hidden.

# Odoo 19 - Automation Rule (PRODUCTION since 29.10.2026)
# Name:          IQ - Return: DHL carrier for Germany
# Model:         Transfer (stock.picking)
# Trigger:       On create and edit
# Apply on:      [("picking_type_code", "=", "incoming"), ("return_id", "!=", False),
#                 ("carrier_id", "=", False), ("state", "not in", ["done", "cancel"])]
# When updating: Carrier, Contact, Type of Operation, Return of, Status
# Action:        Execute Code (below)
#
# Sets DHL Parcel DE + return receiver "deu" on open returns of German customers.
# "On create" alone did not work: Odoo fills "Return of"/state only after create.
# The receiver is set here as well because "DHL - Automatic Return Receiver" does not
# fire while the return is still being created.

carrier = env["delivery.carrier"].search([("name", "=", "DHL Parcel DE")], limit=1)
for picking in records:
    if picking.carrier_id or not carrier:
        continue
    partner = picking.partner_id
    country = partner.country_id or partner.commercial_partner_id.country_id
    if country.code != "DE":
        continue
    vals = {"carrier_id": carrier.id}
    if not picking.dhl_return_receiver_id:
        vals["dhl_return_receiver_id"] = "deu"
    picking.write(vals)
    picking.message_post(body="IQ Return: carrier set to %s, return receiver %s (customer in Germany)." % (carrier.name, picking.dhl_return_receiver_id or "-"))

6. Server action “Send return label”

# Odoo 19 - Server Action (PRODUCTION id 1777, staging id 1774)
# Name:  Send return label
# Model: Transfer (stock.picking), Type: Execute Code, "Create Contextual Action" done
# Used by the buttons "Retourenlabel senden" / "Retourenlabel erneut senden" (view 3).
#
# 1. uses the existing LabelReturn PDF, or creates it via the DHL connector (print_return_label)
# 2. picks template (DE) or (EN) by the customer's language
# 3. opens the email composer on the HELPDESK TICKET if the return belongs to one
#    (customer replies come back into the ticket), otherwise on the return
# 4. attaches the DHL label + the reclamation form (Retourenschein) from the template

picking = record

def find_label(p):
    return env["ir.attachment"].search([
        ("res_model", "=", "stock.picking"), ("res_id", "=", p.id),
        ("mimetype", "=", "application/pdf"), ("name", "ilike", "LabelReturn")], order="id desc", limit=1)

label = find_label(picking)
if not label:
    if not picking.is_return_picking or picking.picking_type_code != "incoming" or picking.state == "done":
        raise UserError("%s is not an open return - no return label can be created." % picking.name)
    if not picking.carrier_id:
        raise UserError("No carrier on %s - please set DHL Parcel DE first." % picking.name)
    picking.print_return_label()
    label = find_label(picking)
    if not label:
        raise UserError("The return label was created, but no 'LabelReturn' PDF was found on %s. Please check the chatter." % picking.name)

lang = (picking.partner_id.lang or "").lower()
key = "(DE)" if lang.startswith("de") else "(EN)"
template = env["mail.template"].search([("model", "=", "stock.picking"), ("name", "ilike", "Return label for customer " + key)], limit=1)
if not template:
    raise UserError("Email template 'IQ – Return label for customer %s' not found." % key)
tmp = env["mail.compose.message"].create({
    "model": "stock.picking", "res_ids": str([picking.id]),
    "composition_mode": "comment", "template_id": template.id})
subject, body = tmp.subject, tmp.body

ticket = env["helpdesk.ticket"]
# .sudo(): ir.model.fields is readable for administrators only (access error for Elena on 29.10.)
if env["ir.model.fields"].sudo().search_count([("model", "=", "helpdesk.ticket"), ("name", "=", "picking_ids")]):
    ticket = env["helpdesk.ticket"].search([("picking_ids", "in", picking.ids)], order="id desc", limit=1)
model, res_id = ("helpdesk.ticket", ticket.id) if ticket else ("stock.picking", picking.id)

composer = env["mail.compose.message"].create({
    "model": model, "res_ids": str([res_id]), "composition_mode": "comment",
    "subject": subject, "body": body,
    "partner_ids": [(6, 0, [picking.partner_id.id])]})
# template attachments are not copied when the composer is created from code -> copy them
form_ids = [att.copy({"res_model": "mail.compose.message", "res_id": composer.id}).id for att in template.attachment_ids]
composer.write({"attachment_ids": [(4, label.id)] + [(4, i) for i in form_ids]})
# no tmp.unlink(): server actions may not delete mail.compose.message (access error); Odoo cleans it up

action = {
    "type": "ir.actions.act_window",
    "name": "Send return label" + (" – Ticket %s" % ticket.display_name if ticket else ""),
    "res_model": "mail.compose.message", "res_id": composer.id,
    "view_mode": "form", "views": [[False, "form"]], "target": "new"}

10. Limits / open items

  • Only orders shipped with DHL: the BrowseInfo connector refuses a return label when the original delivery has no DHL tracking (orders shipped with GLS / before 27.10). For those: create the label manually in the DHL business portal, or ask BrowseInfo to make the check optional.
  • Reply To in the email window showed the sender's personal address (hamza.mohsin@…). Check where a customer reply lands; option: set Reply To to the ticket team alias (customer-care@ / b2b@).
  • Germany only (receiver deu). deu vs deu_SZ decision with Florian still open – if it changes, update this automation and “DHL – Automatic Return Receiver”.
  • Carrier name “DHL Parcel DE” is hard-coded – do not rename the carrier.
  • A German return cannot stay without carrier (the rule sets DHL again when emptied); choose another carrier instead.
  • Price-only Shopify carriers (GLS Deutschland, DHL Paket, GLS EU) can still be validated without label – extension of “Block Validate without Carrier” proposed.
  • Confirm with DHL that unused return labels are not charged.

11. Rollback

  • Button: archive view “IQ – Send return label button”.
  • Automatic carrier: untick Active on “IQ – Return: DHL carrier for Germany”.
  • Templates / server action can stay; nothing else to undo. Labels already created stay on the returns.
