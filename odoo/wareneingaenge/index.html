Goods Receipts App (Wareneingänge)

Odoo 19 · Purchase / Inventory / Quality · Built 2026-11-04 – 2026-11-05 · Owner: Hamza Mohsin · Done in staging – production pending

One card per supplier delivery. Each card pulls the numbers, receipts, quality checks and all files live from the purchase order, so nothing is typed twice. Deliveries without a purchase order and rejected deliveries are added by Excel import, by hand, or with the rejection form. A public read-only calendar shows the warehouse what is coming when.

Background

  • Requested by: Patricia Knabl (quick dashboard of delivery dates) and the TC22 quality topic (documenting defective incoming goods).

What the app contains

MenuWhat it does
Goods ReceiptKanban by status: Expected · Partly booked · Done · Rejected. Sorted by last change. Badges: Overdue, This week, defective, No PO yet. Progress bar, open pieces, kit parts, file count.
Card formTiles (Ordered, Booked, Open, Defective, Files), size × colour table with clickable bookings, tabs: Delivery schedule, Files (upload + preview), Defects, Notes and rejection, Order lines, Receipts, Quality. Chatter.
Upcoming deliveriesPlanned delivery lines, opens in calendar; list grouped by month with totals. Overdue lines red.
Public calendarOpens the public read-only calendar page in a new tab (no login, secret key, no prices). Auto-refresh every 10 minutes.
Import delivery overviewSupplier Excel/CSV → planned lines and cards. Links to POs by vendor reference. Attaches the Excel to each card. Changes are noted in the chatter. PDFs are not read.
Report rejected deliverySupplier or PO, reason (Quality root causes), note, files → card moved to (or created in) Rejected with the files attached.
Configuration → StagesStatus names and order.

How the status moves

EventEffect on the card
PO confirmedCard created in Expected (or an existing no-PO card with the same supplier order no. is linked).
Receipt from the PO validatedAll goods lines fully received → Done; some received → Partly booked; nothing → Expected.
Card in RejectedNever moved automatically.
Inventory adjustmentNo effect (not linked to the PO).
Quality check failNo status change; counts as Defective (failed quantity) and lowers Open.
Receipt with "No backorder" and less than orderedStays Partly booked (PO still expects the rest).

Kits: the PO counts complete sets only; the card shows "Parts X / Y" from the component moves.

Rollout to production

The app lives in the database, not in git. A push or merge to main does not carry it over. It is installed by running one script once.
  1. Production backup in Odoo.sh.
  2. Dry run on a fresh staging copy of production.
  3. Developer mode → Settings → Technical → Scheduled Actions → New (Model: Contact, Active: off) → paste the whole install_wareneingang.py → Save → Run Manually once.
  4. Reload. Check Settings → Technical → Logging, search "IQ" (card count and public calendar link).
  5. Upload the current delivery overview Excel once (staging test data is not carried over).
  6. Test: card on PO confirmation, status on receipt, files, rejection form, public link in a private window, DE/EN.

The script is safe to run again (no deletions). It overwrites manual Studio edits to the "IQ …" views. The install script and the public calendar key are kept in ~/Documents/odoo-customizations/, not in this public repo.
