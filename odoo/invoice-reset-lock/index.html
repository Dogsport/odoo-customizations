Sent invoices: “Reset to Draft” only for admins

User rights, group, view and automation rule so that invoices sent to the customer can no longer be changed.

← Odoo customizations
Prepared by: Hamza Mohsin · Done: 10.11.2026 · Live in production · Asana: Posted invoices: rights and lock date

1. Why

An office user reset five posted customer invoices that had already gone to the tax office (RE/2026/03477, 03817, 04640, 04679, 00566). Example: RE/2026/04679 went from 109.75 € to 113.54 €, so Odoo no longer matched the tax office and the customer showed 3.79 € open. The tax advisor said on 06.11. that changing posted invoices must not be possible.

Root cause: the user did not have Accounting Administrator directly. The group Shopify / Manager (from the Emipro connector) automatically includes Sales Administrator, Accounting Administrator, Inventory Administrator and Shopify User.

Decision (agreed with Florian, 10.11.2026)

Invoice statusWho can use “Reset to Draft”
Posted, not yet sent to the customerEveryone with invoicing rights
Posted and sent to the customerOnly Florian and Patricia

Posting new invoices and credit notes is not restricted. This replaces the Option 1 / Option 2 question from the daily report of 10.11.

<data>
    <!-- normal button: only when the invoice is NOT sent yet -->
    <xpath expr="//button[@name='button_draft']" position="attributes">

    <!-- admin button: only when the invoice IS sent, only for the group -->
    <xpath expr="//button[@name='button_draft']" position="after">
        <button name="button_draft" string="Reset to Draft" type="object"
                groups="custom.group_invoice_posting"
                invisible="not show_reset_to_draft_button or not is_move_sent"/>
    </xpath>
    <xpath expr="//sheet" position="inside">
        <field name="is_move_sent" invisible="1"/>
    </xpath>
</data>

Why two buttons: Odoo can hide a button either by user group (groups) or by record data (invisible), but not both combined on one button. Both call the same method (button_draft), and a user never sees both at once.

2.5 Automation rule (the real lock)

FieldValue
WhereSettings → Technical → Automation → Automation Rules
NameBlock post/reset/cancel invoices for unauthorized users
Model / TriggerJournal Entry / On create and edit
When updatingStatus (only)
Before Update Domainempty
Apply on[("move_type", "in", ["out_invoice", "out_refund", "in_invoice", "in_refund"])]
ActionExecute Code
allowed = (
    env.uid == 1                      # OdooBot / automatic jobs
    or env.user.share                 # public user (Shopify webhooks)
    or env.user.has_group('custom.group_invoice_posting')
)
if not allowed:
    for rec in records:
        if rec.posted_before and rec.is_move_sent and rec.state in ('draft', 'cancel'):
            raise UserError(
                "This invoice was already sent to the customer. "
                "Only Admins can reset it to draft. "
                "Please create a credit note or write a note in the chatter."
            )

This blocks resetting or cancelling a sent invoice for everyone outside the group, even without the button (e.g. import or API).

2.6 Studio (staging only, reverted)

During testing, the standard “Reset to Draft” button was changed in Studio and then reverted. Final state: Allow = Accounting / Invoicing, Forbid = empty. Nothing was changed in Studio in production.

3. How “sent” is detected

The standard field is_move_sent (“Sent”) is set when an invoice goes out from Odoo: the Send button or the automatic invoice email. Checked on Shopify invoice RE/2026/05530: is_move_sent = true.

Limitation: if a PDF is only printed or downloaded and given to the customer outside Odoo, Odoo does not know it was sent, so the normal “Reset to Draft” button stays visible.

5. How to undo

  1. View: Settings → Technical → Views → account.move.form.reset.draft.sent → untick Active.
  2. Rule: Automation Rules → “Block post/reset/cancel…” → archive.
  3. Elena: Shopify back to Manager (gives Accounting Administrator again).
  4. Office: add back to Accounting / Administrator.

Keep the group and the external identifier unless both the view and the rule are removed.
