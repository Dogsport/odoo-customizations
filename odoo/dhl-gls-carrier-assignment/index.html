Carrier assignment: Germany → DHL, international → GLS (26.10.2026)

Status 26.10.2026: tested in Staging (iq-dogsport-staging-40297587), all tests passed. Not yet in Production. Decision by Florian (23.10.2026): Germany ships with DHL, international stays with GLS for now.

Credentials, tokens and customer data are intentionally not stored here. IDs below are Staging IDs — Production IDs must be checked before the rollout (section 7).

1. Target behaviour

SituationDelivery method on the orderCarrier on the delivery
Delivery address in Germany, no method setDHL Parcel DEDHL Parcel DE
Delivery address outside Germany, no method setGLS GermanyGLS Germany (+ GLS incoterm)
Quotation: address changed Germany ↔ abroadswitches DHL ↔ GLSfollows the order
Method chosen by hand (e.g. Direct Sales)kept, never overwrittenkept
Confirmed ordernever changed by the rules–

Principle: the sales order decides the carrier in one place; the delivery takes it over via the route option Propagation of carrier (already ticked on the delivery rules, no change).

2. What was wrong before

  • The carrier was set in four places: rule Shipping add (order) and rules Auto Set Incoterms – EFTA, – Outside EU and Auto Set Carrier (delivery). The three delivery rules always wrote GLS Germany, so a DHL order still ended up with a GLS delivery.
  • Shipping add used the condition ("carrier_id.name", "=", False). In Odoo 17+ a condition through a related field never matches an empty field, so the rule never ran (last_run empty). GLS on deliveries only came from the delivery rules.
  • The rule ran only on create: changing the customer/address on a quotation afterwards kept the old carrier (test S00475: Swiss address with DHL).

7. Read-only checks (Odoo.sh → SHELL)

IDs of Germany and the carriers

PGOPTIONS='-c default_transaction_read_only=on' psql -P pager=off -c "SELECT 'country' AS what, id, code AS name FROM res_country WHERE code='DE' UNION ALL SELECT 'carrier', id, to_jsonb(c)->>'name' FROM delivery_carrier c WHERE active ORDER BY 1, 2;"

Automation rules on orders and deliveries

PGOPTIONS='-c default_transaction_read_only=on' psql -P pager=off -c "SELECT a.id, to_jsonb(a)->>'name' AS name, a.active, a.trigger, m.model, to_jsonb(a)->>'filter_domain' AS apply_on, a.last_run FROM base_automation a JOIN ir_model m ON m.id = a.model_id WHERE m.model IN ('sale.order','stock.picking') ORDER BY m.model, a.id;"

Which field each rule action writes

PGOPTIONS='-c default_transaction_read_only=on' psql -P pager=off -c "SELECT s.base_automation_id AS rule, f.model, f.name AS field, s.value FROM ir_act_server s LEFT JOIN ir_model_fields f ON f.id = (to_jsonb(s)->>'update_field_id')::int WHERE s.state = 'object_write' AND s.base_automation_id IS NOT NULL ORDER BY 1;"

Check the newest orders after go-live

PGOPTIONS='-c default_transaction_read_only=on' psql -P pager=off -c "SELECT so.name, so.carrier_id, c.code AS ship_country, sp.name AS delivery, sp.carrier_id AS delivery_carrier FROM sale_order so LEFT JOIN res_partner p ON p.id = so.partner_shipping_id LEFT JOIN res_country c ON c.id = p.country_id LEFT JOIN stock_picking sp ON sp.sale_id = so.id ORDER BY so.id DESC LIMIT 10;"

Expected: DE → DHL Parcel DE on order and delivery; other countries → GLS Germany.
