Quality control on the TC22 + QC Dashboard

Phone page for checking incoming goods (OK / defect with photos and label), dashboard, details and QC report – built on the standard Odoo Quality app.

← Odoo customizations
Prepared by: Hamza Mohsin · Live: 16.11.2026 · Live in production · TC22 quality documentation task (Florian)

1. Why

Incoming coats were checked on paper: OK tallies per size on cardboard, defects on sticky notes, photos on a phone. Counting, reporting to the supplier and finding the photos again took hours. The goal: one simple phone flow, all data in Odoo, a report per product at any time.

2. How the team uses it

  1. Goods Receipts → QC Dashboard (or the bookmarked link on the TC22) → Start checking.
  2. Choose the product, then the receipt (only purchase-order receipts are listed).
  3. Tap the size. Good coat: choose quantity (1, 2, 3, 5, 10, …) → OK.
  4. Defective coat: Defect → take photos → tap a reason chip (or type a new one) → note → Save & print label. The label prints on the Brother QL-800 and the page goes back to checking.
  5. Dashboard / Details: checked, OK, defects, defect rate, by size, by reason, all photos; Create QC report prints or saves a PDF.

3. How it is built (no new fields)

ThingOdoo record
OK coatquality.check, state pass, product variant = size, receipt
Defective coatquality.check (fail) + quality.alert with reason tag, description, size, receipt
Photosir.attachment on the quality alert
PageServer action "IQ QC page" (website path iq-qc), same link key and team password as the warehouse calendar
MenuGoods Receipts → QC Dashboard (URL action, new tab)
LabelPaper format "IQ QC Label 62x30" (landscape) + hidden report iq_qc.label_62x30, printed via Direct Print / PrintNode; printer in system parameter iq.qc_printnode_printer_id
No stock effect: the page only creates quality records. Receipts are still validated in Odoo as before (only after the quality check – Patricia's rule).

4. Printer

Brother QL-800 with DK-22251 (62 mm continuous, black/red) on the Direct Print client. CUPS/driver settings: media 62 mm, colour 2-Color (Black/Red). A Wi-Fi model (QL-810W / QL-820NWB) can replace it later – only the printer parameter changes.

5. Paper checks imported (one time)

The paper checks 11.–16.11.2026 were collected into a confirmed list and imported with the defect photos through the one-time Papier-Import page: Wintermantel Damen 263 OK + 50 defects, Unisex Winter Parka 90 OK + 4 defects, 78 photos. Coats without a recorded size are stored as size "?" ([Größe unbekannt]). All imported records are marked IQ-QC-IMPORT-2026-11-16; the import page has an undo button.

6. Install / update

Settings → Technical → Scheduled Actions → New (Model: Contact, Active off) → paste qc_2026-11-16_quality_control_page_PRODUCTION.py → Save → Run Manually → F5. Log lines: "IQ QC page installed (v10)" and "IQ QC menu added". Safe to run again. Code is kept in the local folder odoo-customizations/quality-control/.

8. Update 17.11.2026

  • Barcode scanning on the TC22: scan → beep → size shown big → quantity → OK / Defect. Another product switches automatically. Optional Auto-OK.
  • Safeguards: inspector name required, double-scan guard (3 s), progress per size vs. the receipt, "last one was defective".
  • Only open receipts. Defective pieces from incoming deliveries are never booked; defects found after booking go to the defects/repair process.
  • "Hinweis – kein Defekt": unusual but acceptable pieces with photos – booked, no label, shown separately.
  • Booking overview per receipt and new receipt button "QC: OK-Mengen übernehmen" (Action ⚙, Inventory Administrators): sets quantity = OK count, does not validate, writes a summary into the chatter.
  • Standard "QC Wareneingang" checks from Quality Control Points are ignored in the counts. Phone layout for all pages.
