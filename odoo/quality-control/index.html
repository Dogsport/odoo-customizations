Quality control on the TC22 + QC Dashboard

Phone page for checking incoming goods (OK / defect with photos, defect places and label), dashboard, details, QC report, packing defects into labelled boxes with a check against Odoo, and manager login – built on the standard Odoo Quality app.

← Odoo customizations
Prepared by: Hamza Mohsin · Live: 16.11.2026 · Last update: 20.11.2026 (v19.16.8) · Live in production · TC22 quality documentation task (Florian)

1. Why

Incoming coats were checked on paper: OK tallies per size on cardboard, defects on sticky notes, photos on a phone. Counting, reporting to the supplier and finding the photos again took hours. The goal: one simple phone flow, all data in Odoo, a report per product at any time.

2. How the team uses it

  1. Goods Receipts → QC Dashboard (or the bookmarked link on the TC22) → Start checking.
  2. Choose the product, then the receipt (only purchase-order receipts are listed).
  3. Tap the size. Good coat: choose quantity (1, 2, 3, 5, 10, …) → OK.
  4. Defective coat: Defect → take photos → tap a reason chip (or type a new one) → note → Save & print label. The label prints on the Brother QL-800 and the page goes back to checking.
  5. Dashboard / Details: checked, OK, defects, defect rate, by size, by reason, all photos; Create QC report prints or saves a PDF.

Brother QL-800 with DK-22251 (62 mm continuous, black/red) on the Direct Print client. CUPS/driver settings: media 62 mm, colour 2-Color (Black/Red). A Wi-Fi model (QL-810W / QL-820NWB) can replace it later – only the printer parameter changes.

10. Update 20.11.2026 (v19.16 – v19.16.5): manager login, packing defects, handovers

10.1 Manager login on the QC page

  • Button Anmelden top right. Uses the same manager PIN as the Lager- & Teamkalender (system parameter iq.delivery_calendar_manager_pin, at least 8 characters).
  • The login lasts 30 minutes; the button then shows Abmelden (xx Min.). Logging in on the QC page also logs you in on the calendar and the other way round (same session cookie).
  • 5 wrong PINs → that login is locked for 15 minutes (same counter as the calendar).
  • While logged in, saving a drawing asks for no PIN.

10.2 Top bar

New links on every QC page: Verpacken (Defekte verpacken), Kalender (Lager- & Teamkalender) and Anmelden / Abmelden. The calendar got a QC Dashboard link back.

10.3 Defekte verpacken (pack defects into boxes)

Black button under "Prüfen starten" on the dashboard. Anyone can use it, no login. Goal: the number of defective pieces in the boxes always matches Odoo (example: Wintermantel – Odoo said 55, the boxes held 63).

  1. Choose the product → choose the delivery → Karton 1 beginnen. The box number is set automatically.
  2. Scan each defective piece (TC22 scanner, no Enter needed, the field does not need to be tapped) or tap the size. Beep + green line "✓ Gr. M – jetzt 5 Stk. in diesem Karton". Wrong product or unknown barcode → low beep + red message. − / + to correct.
  3. Karton abschließen & Etikett drucken → label on the Brother (RAW) or as PDF: KARTON n, DEFEKT, each size with article number and count, total, "NICHT BUCHEN", date, delivery.
  4. Closed boxes: Etikett (reprint), PDF, Öffnen (reopen to change). An empty box can be deleted (to remove a box with items: reopen, − to 0, "Leeren Karton löschen").

10.4 Comparison Odoo ↔ boxes

Below the box, per size: Odoo Defekte · In Kartons · Abgegeben · Differenz. Difference = boxes + handed over − Odoo. ✓ = matches, red = check. The product name is shown above the table.

  • + = more pieces than in Odoo (found while packing, not recorded). A logged-in manager can use Fehlende in Odoo nachtragen: creates one defect per piece with reason "Beim Verpacken gefunden" (no photo), on the chosen delivery, marked [IQ-QC-PACK].
  • − = Odoo has more than packed: pieces not packed yet, missing, or recorded under another size.
  • "? (ohne Größe)" = defects from the paper import without size.

10.5 Already handed over (managers only)

  • Abgabe erfassen: pieces that already left (e.g. the supplier took them): who / where, date, delivery, count per size or "Größe unbekannt". They count in the "Abgegeben" column, not in a box.
  • Karton abgegeben on a closed box: asks who took it and the date. The whole box moves from "In Kartons" to "Abgegeben"; nothing is typed twice. Label/PDF still work. Rückgängig undoes it. A handed-over box cannot be reopened.
Example 20.11.2026 – Holfelder (P00053, MFJ 4.0): Holfelder took the non-sellable jackets from the quality reports: Women 8 (Schwarz XS, M, L, 3XL, 4XL × 1; grau M × 1, XL × 2), Unisex 2 (grau S × 2). Recorded as handovers. Unisex: Odoo 2 = handed over 2 ✓. Women: Odoo 16 = 8 handed over + 8 in Box 1 ✓.

10.9 QC report (from the details page: "QC-Bericht erstellen")

  • IQ Dogsport logo at the top, then the status: orange "ZWISCHENSTAND – NICHT FINAL" while the check is open; no banner and title "Endbericht" once a manager has completed the check.
  • Only real defects: "Hinweis – kein Defekt" entries and the Hinweis column are left out. No inspector names, no links (nothing in the PDF is clickable, the browser header/footer with the page link is not printed).
  • Every photo is shown complete (not cropped): 2 photos side by side, 1 photo full width; the defect place drawing below.
  • The button "Drucken / als PDF speichern" is only active once all photos have loaded ("Fotos werden geladen … 3/8").

10.10 Completing the check of a product (managers)

The details page shows a status bar: orange "Prüfung läuft" or green "✓ Prüfung abgeschlossen am …". A logged-in manager taps "Prüfung abschließen" (optional remark) – from then on the QC report is the final report. "Wieder öffnen" makes it an interim report again (e.g. when more pieces arrive). Stored as attachment iq_qc_done.txt on the product (date|remark), no new field.

10.11 Editing a defect (managers)

  • Defect cards on the details page have "Bearbeiten". It opens the same screen as creating a defect, already filled in: change reasons and places, size, note, remove photos (tick), switch Defekt ↔ Hinweis – kein Defekt.
  • "✓ Änderungen speichern" saves only the changes – no label is printed. A new label only if "Danach Etikett neu drucken" is ticked (optional).
  • Every change is written into the chatter of the quality alert ("Geändert auf der QC-Seite (Führungskraft, date): Typ / Größe / Grund/Ort / Fotos / Notiz").

10.12 Easier for new inspectors

  • Name first: the start page and the check page begin with a red card "Wer prüft? Bitte zuerst deinen Namen eingeben". Scanning or saving without a name shakes the card and puts the cursor into the field. Once filled in it becomes one line "✓ Prüfer: Name · ändern"; the phone remembers the name.
  • Scanning always works: scanner input is recognised by its speed even when the cursor is in a text field (search, name); the code is removed from the field and handled as a scan. Normal typing is not affected.

10.13 Protection of the link

  • Team password: 5 wrong tries → locked for 15 minutes (counter iq.qc_pwfail). The page is marked "noindex" (not listed by search engines).
  • Inspectors (team password) can see dashboard, details and reports but cannot edit, delete or complete anything.
  • Recommended: a long random link key (iq.delivery_calendar_key, nobody types it – bookmark + menu) and a pass phrase of 3–4 words with a number as team password (iq.delivery_calendar_password). After a key change run "IQ Calendar: update menu link" and update the bookmark on the TC22. The calendar uses the same key and password.
