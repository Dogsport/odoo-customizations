2. The problem

EU business customers (outside Germany) can enter a VAT ID in the Shopify checkout. Shopify validates it and applies reverse charge ("Reverse charge was applied. A valid VAT number: HU… was provided for this order."). Two things went wrong:

  1. Odoo: the Emipro connector does not import the VAT ID (it is only in the Shopify order events, not in the REST order data, localizedFields or customAttributes). In Odoo the customer had no VAT ID, the order got the OSS fiscal position of the customer's country (e.g. "OSS B2C Hungary" 27%) and the invoice showed VAT the customer never paid.
  2. Shopify price: with fixed tax-inclusive prices ("Show as included"), Shopify removes the VAT but keeps the gross price. Example: jacket €279.90 → business with valid VAT ID still pays €279.90, tax €0.00 (should be ≈ €235.21 net). Customers then ask for a refund (e.g. Fodor).

Since April this happened in 14 orders (list from Patricia): #IQD-94603, 94847, 96441, 96555, 96556, 97075, 97529, 98321, 98713, 98815, 98874, 98902, 99056, 99141. Two were dealers who ordered as normal customers instead of via their company account (#IQD-96555/96556 The Kill, #IQD-98815 Edog). New case on 28.10: #IQD-99202 (HU18283822, €308.80, bank deposit pending).

3. Findings

3.1 Odoo setup was already right – only the input was missing

  • Fiscal position 6 "Business partner EU (with VAT ID)" (auto apply, VAT required, EU country group, 0% EU D, account 812500) and the OSS B2C positions exist and work.
  • VIES check: production on since 27.10 (Patricia), staging switched on 28.10.
  • Customers that already have a VAT ID in Odoo (dealers) automatically get fiscal position 6. Production check: of 83 EU orders since 01.04 from customers with a VAT ID, 76 were invoiced correctly.
  • Emipro sets the fiscal position from the Shopify market (prepare_shopify_order_vals, sale_order.py) and creates order lines without tax when Shopify sends no tax lines.
  • The VAT ID is only available via GraphQL order events; instance.get_graphql_client().execute() can be called from an automation (safe_eval).

3.2 Shopify behaviour

  • Fixed / "Show as included" / line item: VAT ID → tax line becomes €0, price stays. There is no setting to change this.
  • Dynamic tax-inclusive pricing: Shopify takes out the German 19% and adds the customer's VAT. With a valid VAT ID the VAT is removed and the price drops. Test store: Hungary private €280.80 (with −6% HU sub-market), with VAT ID €221.10.
  • Market price adjustments only accept whole percentages; one percentage per market. Grow plan reportedly allows only 3 markets (Basic/Grow 3, Advanced 3–50, Plus 50) – to be confirmed in admin.
  • Checkout customization and private Shopify Functions need Shopify Plus (~$2,300+/month). Even on Plus, custom code cannot read Shopify's native VAT field.
  • Since 01.01.2026 new legacy custom apps cannot be created in the Shopify admin. Dev Dashboard apps install directly only on development stores; the custom install link for the test store was rejected ("installation link is invalid"). The existing "Odoo Staging Connector" has no draft_orders scope.

3.3 Dealers (Shopify B2B companies)

  • Dealers are Shopify Companies (Customers → Companies) with catalog IQ-Händler-B2B-Gold (fixed net prices, e.g. Sommerweste 3.0 €79.90 vs. retail €129.90) and location tax setting "Don't collect tax".
  • Proof: #IQD-99203 CaniTess (BE) – dealer prices, no tax in Shopify, Odoo 0% EU D, totals equal (€1,213.57).
  • Edog Kalypsoland: location switched to "Don't collect tax" by Chantal on 16.06; #IQD-95400 (25.05) was before that and was charged 21% RO VAT in Shopify (still "payment pending"; Odoo invoice RE/2026/01277 at 0%).
  • Company locations often have no VAT number stored ("VAT number: Not provided"). Several companies show "No main contact" (ordering still possible via assigned customers).
  • Dynamic does not adjust fixed catalog prices – dealers should be unaffected (to be verified with one company order after the switch).

3.4 Open finding

#IQD-98746 and #IQD-94400 (Austria): Shopify charged no VAT although there was no company and no VAT ID. Cause not found yet (customer tax exempt? draft order without tax? product "charge tax" off? Austria override?).

# Odoo 19 - Automation Rule (PRODUCTION since 28.10.2026)
# Name:     IQ - EU VAT from Shopify reverse charge
# Model:    Sales Order (sale.order)
# Trigger:  On create
# Apply on: see domain_automation_1.txt
# Action:   Execute Code (paste everything below this header)
#
# What it does: when Shopify applied reverse charge ("Reverse charge was applied.
# A valid VAT number: XX..." in the Shopify order events), store the VAT ID on the
# customer (Odoo runs the VIES check), set the "VAT required" fiscal position
# (Business partner EU (with VAT ID)), update taxes (0% EU D) and post a note.
# Never changes prices. Skips dealers that already have VAT + B2B fiscal position.

MARK = "A valid VAT number:"
QUERY = "query($id: ID!) { order(id: $id) { events(first: 50) { nodes { message } } } }"
for order in records:
    try:
        if not order.shopify_order_id:
            continue
        partner = order.partner_invoice_id.commercial_partner_id
        # dealer with VAT already in Odoo and correct fiscal position -> nothing to do
        if partner.vat and order.fiscal_position_id.vat_required:
            continue
        country = order.partner_shipping_id.country_id
        code = country.code or ""
        res = order.shopify_instance_id.get_graphql_client().execute(QUERY, {"id": "gid://shopify/Order/%s" % order.shopify_order_id})
        if not isinstance(res, dict):
            res = res.to_dict()
        so = (res.get("data", res) or {}).get("order") or {}
        vat = False
        for ev in ((so.get("events") or {}).get("nodes") or []):
            msg = ev.get("message") or ""
            if "Reverse charge was applied" in msg and MARK in msg:
                vat = msg.split(MARK)[1].strip().split(" ")[0].strip()
        if not vat:
            continue
        prefix = "EL" if code == "GR" else code
        if not vat.startswith(prefix) or not vat.isalnum():
            order.message_post(body="IQ VAT: VAT %s does not match delivery country %s - nothing changed, please check." % (vat, code))
            continue
        # 1. store VAT ID on the customer (Odoo runs the VIES check)
        if not partner.vat:
            partner.write({"vat": vat})
            partner.message_post(body="VAT ID %s taken from Shopify order %s." % (vat, order.name))
        elif partner.vat.replace(" ", "").upper() != vat:
            order.message_post(body="IQ VAT: customer already has VAT %s, Shopify says %s - customer not changed, please check." % (partner.vat, vat))
            continue
        # 2. fiscal position + taxes, only if not already B2B
        if not order.fiscal_position_id.vat_required:
            fp = env["account.fiscal.position"].search([
                ("auto_apply", "=", True), ("vat_required", "=", True),
                ("country_group_id.country_ids", "in", country.id),
                ("company_id", "in", [order.company_id.id, False])], order="sequence", limit=1)
            if fp:
                order.write({"fiscal_position_id": fp.id})
                if order.order_line and order.invoice_status != "invoiced":
                    order.action_update_taxes()
        order.message_post(body="IQ VAT: This order contains VAT ID %s (Shopify reverse charge). Customer updated, fiscal position: %s." % (vat, order.fiscal_position_id.display_name))
    except Exception as e:
        order.message_post(body="IQ VAT: could not process VAT ID: %s" % e)

Automation 2 – Sales Order Line, on create

# Odoo 19 - Automation Rule (PRODUCTION since 28.10.2026)
# Name:     IQ - EU VAT: 0% tax on reverse-charge lines
# Model:    Sales Order Line (sale.order.line)
# Trigger:  On create
# Apply on: [("order_id.shopify_instance_id", "!=", False), ("order_id.fiscal_position_id.vat_required", "=", True)]
# Action:   Execute Code
#
# Safety net: Emipro creates order lines WITHOUT tax when Shopify sends no tax lines
# (reverse charge). Such a line gets the product tax mapped through the order's
# fiscal position (-> 0% EU D). Lines that already have a tax are never touched.

tax_field = "tax_ids" if env["ir.model.fields"].search_count([("model", "=", "sale.order.line"), ("name", "=", "tax_ids")]) else "tax_id"
for line in records:
    try:
        order = line.order_id
        fp = order.fiscal_position_id
        if not fp or not fp.vat_required or line[tax_field] or not line.product_id:
            continue
        taxes = line.product_id.taxes_id.filtered(lambda t: t.company_id == order.company_id)
        mapped = fp.map_tax(taxes)
        if mapped:
            line.write({tax_field: [(6, 0, mapped.ids)]})
            order.message_post(body="IQ VAT: line '%s' -> tax %s (fiscal position %s)." % (line.product_id.display_name, ", ".join(mapped.mapped("name")), fp.display_name))
    except Exception as e:
        line.order_id.message_post(body="IQ VAT: tax on line skipped because of an error: %s" % e)

Dry run server action (read only)

# Odoo 19 - Server Action (read only report, changes nothing)
# Name:  IQ - VAT dry run (read only)
# Model: Sales Order, Type: Execute Code, then "Create Contextual Action".
# Use:   select orders > Action > IQ - VAT dry run (read only) -> popup report.

MARK = "A valid VAT number:"
QUERY = "query($id: ID!) { order(id: $id) { totalTaxSet { shopMoney { amount } } events(first: 50) { nodes { message } } } }"
out = []
for order in records:
    try:
        code = order.partner_shipping_id.country_id.code or ""
        if not order.shopify_order_id or not order.shopify_instance_id:
            out.append("%s: not a Shopify order - skip" % order.name)
            continue
        res = order.shopify_instance_id.get_graphql_client().execute(QUERY, {"id": "gid://shopify/Order/%s" % order.shopify_order_id})
        if not isinstance(res, dict):
            res = res.to_dict()
        so = (res.get("data", res) or {}).get("order") or {}
        tax = float(((so.get("totalTaxSet") or {}).get("shopMoney") or {}).get("amount") or 0)
        vat = False
        for ev in ((so.get("events") or {}).get("nodes") or []):
            msg = ev.get("message") or ""
            if "Reverse charge was applied" in msg and MARK in msg:
                vat = msg.split(MARK)[1].strip().split(" ")[0].strip()
        out.append("%s: %s | Shopify tax %.2f | reverse-charge VAT: %s | Odoo fiscal position: %s | Odoo tax %.2f"
                   % (order.name, code, tax, vat or "-", order.fiscal_position_id.display_name or "-", order.amount_tax))
    except Exception as e:
        out.append("%s: error %s" % (order.name, e))
raise UserError("\n".join(out))

13. Read-only queries

Run with PGOPTIONS='-c default_transaction_read_only=on' psql -P pager=off -c "…".

-- All read only. Run on Odoo.sh shell with:
-- PGOPTIONS='-c default_transaction_read_only=on' psql -P pager=off -c "<query>"

-- 1. Emipro tax setting (decides whether Odoo or Shopify taxes are used on import)
SELECT id, name, apply_tax_in_order FROM shopify_instance_ept;

-- 2. VIES check switch per company
SELECT id, name, vat_check_vies FROM res_company;

-- 3. EU orders since 01.04 where the customer has a VAT ID but VAT was charged
SELECT so.name, so.date_order::date, c.code AS country, cp.vat, cp.vies_valid,
       fp.name->>'en_US' AS fiscal_position, so.amount_untaxed, so.amount_tax, so.amount_total
FROM sale_order so
JOIN res_partner p ON p.id = so.partner_invoice_id
JOIN res_partner cp ON cp.id = p.commercial_partner_id
LEFT JOIN res_partner sh ON sh.id = so.partner_shipping_id
LEFT JOIN res_country c ON c.id = sh.country_id
LEFT JOIN account_fiscal_position fp ON fp.id = so.fiscal_position_id
WHERE so.name LIKE '#IQD-%' AND so.date_order >= '2026-04-01' AND so.state <> 'cancel'
  AND coalesce(cp.vat,'') <> '' AND c.code <> 'DE'
ORDER BY so.amount_tax DESC, so.date_order;

-- 4. Orders touched by the new automations (chatter notes)
SELECT m.date, so.name, left(regexp_replace(m.body, '<[^>]+>', '', 'g'), 160) AS note
FROM mail_message m JOIN sale_order so ON so.id = m.res_id AND m.model = 'sale.order'
WHERE m.body LIKE '%IQ VAT:%' ORDER BY m.date DESC LIMIT 50;

-- 5. Shopify vs Odoo totals after the Dynamic switch (compare with Shopify admin)
SELECT so.name, so.date_order::date, c.code, fp.name->>'en_US' AS fiscal_position,
       so.amount_untaxed, so.amount_tax, so.amount_total
FROM sale_order so
LEFT JOIN res_partner sh ON sh.id = so.partner_shipping_id
LEFT JOIN res_country c ON c.id = sh.country_id
LEFT JOIN account_fiscal_position fp ON fp.id = so.fiscal_position_id
WHERE so.name LIKE '#IQD-%' AND so.date_order >= '2026-10-28 17:00'
ORDER BY so.date_order;
