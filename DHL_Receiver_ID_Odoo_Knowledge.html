DHL Return Receiver ID – Odoo 19

IQ Dogsport GmbH • Staging tested 13 October 2026 • Internal Knowledge article

1. The original issue

Every new DHL return had an empty DHL Return Receiver ID. Staff had to open Get Receivers, fetch choices, and select one manually. We wanted new German DHL returns to default to deu but still allow an override.

2. Exactly what we created

3. The automation

Navigation: Settings → Technical → Automation → Automation Rules → DHL – Automatic Return Receiver.

FieldSetting
ModelTransfer (stock.picking)
TriggerOn create and edit
Before Update DomainMatch all records
Apply on[('dhl_return_receiver_id', '=', False)]
When updatingCarrier, Contact, Operation Type; do not include Receiver ID
Actions To DoExecute Code

Why this action?

Update Record alone would not express the checks for an incoming German DHL return and preserving manual changes. Execute Code writes the existing dhl_return_receiver_id only when it is empty.

# Model: stock.picking | Odoo Automated Action - Execute Code
pickings = records or record or env['stock.picking']
for picking in pickings:
    if not picking.is_dhl_return:
        continue
    if picking.picking_type_id.code != 'incoming':
        continue
    if picking.carrier_id.delivery_type != 'dhl_parcel_de':
        continue
    if picking.state in ('done', 'cancel'):
        continue
    if picking.dhl_return_receiver_id:
        continue   # Preserve manual choices
    if picking.partner_id.country_id.code == 'DE':
        picking.write({'dhl_return_receiver_id': 'deu'})
        log('DHL receiver deu assigned to %s' % picking.name, level='info')

6. Production rollout — repeat in LIVE

Essential: Odoo.sh staging database changes do not automatically transfer to the production database. Copy the settings and XML manually or deploy using a version-controlled Odoo module.

  1. Back up Production; verify compatible BrowseInfo DHL connector installed.
  2. Verify the actual DHL business return address, Receiver ID deu and billing contract in the DHL Business Customer Portal.
  3. Confirm approved DHL Returns production API permissions and the BrowseInfo production setup; do not use sandbox keys for live requests.
  4. Create the same one automation in Production with the same model, domain, triggers and Python code.
  5. Find the BrowseInfo parent view in Production by name (not Staging ID), create the one extension view with the XML above; leave Website empty.
  6. Check carrier rules so “Auto Set Carrier” does not override DHL to GLS.
  7. Create a new German DHL return and verify Receiver ID deu + Change Receiver before generating a label; test manual override.
  8. When authorized, print one real test label and confirm IQ Dogsport’s actual receiving address and live tracking; do not validate the receipt before goods arrive.
